# 个人博客改版设计

## 目标

网站用于分享有趣的技术内容、记录学习过程，也容纳生活随笔。访客应能快速找到文章，分辨正式内容与版式示例，并且无需注册就能参与讨论。`https://leyang-xia.github.io/` 是正式主站；Sites 版本用于预览。

参考[辰渊尘の博客](https://blog.mcxiaochen.top/)的图文层次、简明文库和公开留言板，同时延续本站已有的留白、字体层级、明暗主题和克制的交互。

## 页面与导航

主导航为**首页、文库、留言板、关于**，右侧保留搜索和明暗切换。移除现有的**研究**页面及入口。现有 `/writing/` 路径保持不变，导航名称和页面标题改为**文库**；留言板使用 `/guestbook/`；关于页继续使用 `/about/`。现有文章地址保持不变。

技术分享、学习记录与生活随笔共用一个文章集合。标签依据实际内容命名，不固定使用“技术分享”“学习记录”作为栏目名。正式文章必须有发布日期。现有三篇示例文章保留且显著标明**示例稿**，单列在**版式预览**区，不混入按年份排列的正式文章。

## 首页

桌面版采用主内容栏和窄侧边栏。主内容栏从一句简短、具体的个人介绍开始，接着展示一篇重点文章、最近文章和可点击的标签。现有首页已经有精选内容；改版只调整呈现方式，不再叠加一个精选区。重点文章有封面时显示封面，没有封面时用排版和低对比色块组成文字卡片。侧边栏包含头像或姓名字母、简短介绍、关于页与 GitHub 链接，以及从文章集合自动取得的最近文章入口。

窄屏按“介绍、重点文章、个人卡片、文章列表”的顺序纵向排列。交互元素须有可见的键盘焦点；动效仅用于短暂反馈，并遵守系统的减少动态效果设置。沿用当前明暗主题的选择与持久化行为。

## 文库与文章

文库中的正式文章按年份分组，组内按发布日期从新到旧排列。每行展示日期、标题、简短摘要和标签。点击标签后，地址变为可分享的 `/writing/?tag=...`，在不改变原顺序的情况下筛选文章；点击**全部**恢复完整列表。关闭 JavaScript 时，链接仍能打开完整文库。三篇无日期的示例稿置于独立的**版式预览**区，并逐篇标识。搜索同时覆盖正式文章和示例稿，结果中也应标明示例稿。

文章页展示标题、摘要、正式发布日期、标签、可选封面、正文和讨论区。示例稿显示**示例稿**而不编造日期。正文在 JavaScript 不可用时仍能阅读；搜索、标签筛选、主题切换和评论作为增强功能加载。

## 留言板与文章评论

留言板包含简短的邀请文字、留言表单和公开回复区。每篇文章末尾也使用同一评论系统。访客无需账号；昵称和内容必填，邮箱选填且不会公开展示，表单说明其用途。所有留言和回复在站长审核前均不公开。提交后应明确提示“等待审核”。评论服务不可用时，页面内容仍正常显示，并给出清楚的不可用提示。

评论系统采用 [Twikoo](https://twikoo.js.org/intro.html)：官方文档支持免登录评论、回复、管理和人工审核。GitHub Pages 仅托管静态前端。后端按 [Twikoo 部署文档](https://twikoo.js.org/backend.html)运行在 Netlify Functions，数据存储于 MongoDB Atlas。公开的后端地址在构建时注入；数据库凭据只存放于后端平台的密钥设置，不能提交进仓库。每篇文章用稳定的站内路径标识评论线程；`/guestbook/` 使用独立线程。前端只在 GitHub Pages 主站启用真实评论；Sites 预览显示提示，不向正式评论库写入。浏览器端的域名判断并非后端访问控制，因此仍需审核。

站长在评论管理后台批准或拒绝留言。正式开放前须验证后台登录、审核状态、回复流程，以及数据导出或备份办法。评论平台账号和数据库凭据是上线真实留言功能所需的外部准备。

## 内容与构建

继续使用现有 Python 生成器作为静态站点的来源。文章记录明确包含 `slug`、`title`、`summary`、`tags`、`status`（`sample` 或 `published`）、可选 `published_at`、可选 `cover` 和正文。生成器须校验：正式文章有日期、示例稿不冒充正式文章、`slug` 不重复、封面路径存在。生成结果包括首页、文库、文章、留言板、关于、搜索数据和 404 页面。静态资源继续放在 `assets/`；构建结果同步到仓库根目录，供 GitHub Pages 发布。

GitHub Pages 当前从 `main` 分支根目录发布，正式发布仍需提交并推送到 `main`。Sites 保持独立的预览流程；预览操作不得写入正式评论。

## 验证

- 从生成器构建，并核对生成文件与仓库根目录的发布副本一致。
- 检查首页、文库、文章、留言板、关于和 404 页的站内链接及资源。
- 检查桌面与手机布局、键盘导航、焦点、减少动态效果和明暗主题的可读性。
- 使用至少一篇有日期的文章样本和一篇示例稿，验证年份排序、标签筛选、示例区及搜索结果。
- 在正式站点提交一条留言和一条文章回复，确认审核前不可见、审核后可见；确认预览站无法提交到正式评论库。
- 断开评论后端时，确认页面内容和导航仍可用。

## 交付边界

这份设计同时覆盖静态页面改版和评论集成。页面可以先构建并预览；留言板只有在后端、数据库和审核账号配置完成，且正式站点的提交流程验证通过后，才算实现。
